# 软件说明书

# 基于AI的智能测试编排与验证系统 V1.0

---

## 1 软件概述

### 1.1 软件名称

基于AI的智能测试编排与验证系统（以下简称"本系统"）

### 1.2 软件版本

V1.0

### 1.3 软件功能简介

本系统是一款基于人工智能技术的端到端自动化测试编排与验证平台。系统通过AI分析模块间API数据流，自动推断跨模块的依赖关系和变量映射，构建依赖图并通过拓扑排序自动编排测试执行链路。内置三层断言引擎，在单一测试执行过程中同时对UI层、API层和数据库层进行联动验证，并支持数据库不可达时的优雅降级。系统提供统一的命令行管理界面，集成录制、编排、执行、报告等全流程测试能力。

### 1.4 软件用途

本系统适用于Web应用的复杂业务流程自动化测试，特别是涉及多个模块顺序执行、变量传递和数据一致性验证的场景。典型应用包括采购管理流程（创建→审核→确认）、行政审批流程（提交→审批→归档）、电商交易流程（下单→支付→发货）等端到端业务测试。

## 4 功能说明

### 4.1 功能结构图

本系统包含以下核心功能模块：

- **AI依赖推断模块**：分析模块间API数据流，自动推断依赖关系
- **依赖图引擎**：构建模块依赖有向图，拓扑排序生成执行链
- **执行计划编排模块**：根据依赖图生成完整执行计划
- **变量桥接模块**：管理跨模块的变量传递和模板替换
- **三层断言引擎**：统一调度UI/API/DB三层断言验证
- **报告生成模块**：汇总断言结果生成结构化报告
- **统一命令行管理模块**：提供record/run/compose/heal/report等子命令

### 4.2 AI依赖推断功能

#### 4.2.1 功能描述

通过AI分析已录制模块的API数据流，自动推断模块间的依赖关系。系统能够识别上游模块API响应中产出的变量（如需求编号）被下游模块API请求中引用的关系，并生成变量映射表。

#### 4.2.2 推断策略

系统采用双轨推断策略：

**规则匹配（高置信度）**：
- 递归提取API响应中的ID类字段（如 `data.id`、`data.uuid`）
- 将提取的ID值与后续API请求体中的参数值进行精确匹配
- 匹配成功则建立依赖关系，置信度为0.85

**AI语义分析（补充隐含依赖）**：
- 将API请求序列和参数结构发送给大语言模型
- AI理解API的业务语义，推断规则匹配无法发现的隐含依赖
- 可选注入前端知识文档作为AI上下文，提升推断准确率
- AI返回依赖关系和置信度，低于阈值的标记为待确认

#### 4.2.3 操作步骤

依赖推断在录制过程中自动执行。也可通过查询命令查看推断结果：

```
python cli.py query-knowledge --graph
```

输出示例：

```
依赖图:
   create_demand → audit_demand [demand_id]
   audit_demand → confirm_demand [audit_result]
```

### 4.3 测试链编排功能

#### 4.3.1 功能描述

根据AI推断的依赖关系构建模块依赖有向图，通过深度优先搜索（DFS）拓扑排序，自动计算从根模块到目标模块的前置执行链，生成包含变量来源和产出信息的执行计划。

#### 4.3.2 编排流程

1. 加载所有已录制模块的定义信息
2. 构建模块依赖有向图（节点=模块，边=依赖关系+变量映射）
3. 从目标模块出发，DFS遍历所有前置依赖
4. 拓扑排序生成执行链（依赖在前，被依赖在后）
5. 为每个执行步骤标注所需变量来源和产出变量

#### 4.3.3 操作步骤

**查看编排计划（不执行）**：

```
python cli.py compose confirm_demand
```

输出示例：

```
执行计划: confirm_demand
执行链: create_demand → audit_demand → confirm_demand

  Step 0: create_demand
    产出: demand_id

  Step 1: audit_demand
    需要: {"demand_id": "from_module:create_demand"}
    产出: audit_result

  Step 2: confirm_demand
    需要: {"demand_id": "from_module:create_demand", "audit_result": "from_module:audit_demand"}
```

**保存编排计划到文件**：

```
python cli.py compose confirm_demand --save plan.json
```

### 4.4 测试链执行功能

#### 4.4.1 功能描述

按照编排计划顺序执行测试链，逐模块执行增强脚本，自动进行模块间的变量传递、自愈修复和三层断言验证。

#### 4.4.2 执行流程

1. 加载编排计划，按执行链顺序逐模块执行
2. 每个模块执行前，变量桥接器将上下文变量注入到执行环境
3. 执行增强脚本（支持自愈修复）
4. 执行完成后提取产出变量，写入上下文
5. 对每个模块执行三层断言验证
6. 汇总所有模块的执行结果和断言结果

#### 4.4.3 操作步骤

**执行测试链**：

```
python cli.py run confirm_demand
```

参数说明：
- `confirm_demand`：目标模块名
- `--headed`：有头模式执行（可观察操作过程）
- `--var key=value`：注入外部变量（可多次使用）

**带外部变量执行**：

```
python cli.py run confirm_demand --var demand_id=XQ-2026-001
```

**查看执行结果**：

```
python cli.py report
```

### 4.5 变量桥接功能

#### 4.5.1 功能描述

管理跨模块的变量自动传递，支持模板变量机制（`{{var_name}}`），将运行时动态值注入到后续模块的脚本、API断言和SQL查询中。

#### 4.5.2 变量传递链路

```
模块A执行 → 提取变量 demand_id=XQ-001
  → 写入上下文 context_vars["demand_id"] = "XQ-001"
  → 注入到环境变量 TEST_CONTEXT_VARS
  → 模块B执行时自动替换 {{demand_id}} 为 XQ-001
```

#### 4.5.3 模板替换能力

- **字符串替换**：将 `{{demand_id}}` 替换为实际值
- **嵌套字典替换**：递归替换字典中所有字符串值中的模板
- **列表替换**：递归替换列表中所有字符串元素中的模板
- **SQL替换**：将 `SELECT * FROM demand WHERE id='{{demand_id}}'` 中的模板替换为实际值

### 4.6 三层断言验证功能

#### 4.6.1 功能描述

在单一测试执行过程中，同时对UI层、API层和数据库层进行断言验证。支持多种断言类型，并提供统一的报告汇总。

#### 4.6.2 UI层断言

| 断言类型 | 说明 | 示例 |
|---------|------|------|
| 可见性 | 验证元素是否可见 | 验证"提交成功"提示可见 |
| 文本内容 | 验证元素文本包含期望值 | 验证页面标题包含"采购需求" |
| URL | 验证当前URL包含期望路径 | 验证跳转到 `/demand/detail` |
| 数量 | 验证元素数量 | 验证列表中有3条记录 |
| 可用性 | 验证按钮是否可点击 | 验证"提交"按钮可用 |

#### 4.6.3 API层断言

| 断言类型 | 说明 | 示例 |
|---------|------|------|
| 状态码 | 验证HTTP状态码 | POST /demand/create 返回 200 |
| 业务code | 验证响应体中的业务状态码 | 验证 `code=0` |
| 字段值 | 验证响应体中指定字段的值 | 验证 `data.status=draft` |
| 响应头 | 验证响应头信息 | 验证Content-Type包含json |

API层断言支持变量模板：期望值中使用 `{{var_name}}` 引用运行时变量。

#### 4.6.4 DB层断言

| 断言类型 | 说明 | 示例 |
|---------|------|------|
| 记录存在 | 验证SQL查询有结果 | 验证需求记录已写入数据库 |
| 字段值 | 验证查询结果的字段值 | 验证status字段值为 `draft` |
| 数量 | 验证查询结果的数量 | 验证有1条审核记录 |

DB层断言特性：
- **变量模板注入**：SQL语句中使用 `{{var_name}}` 引用运行时变量
- **优雅降级**：数据库不可达时自动跳过，断言状态标记为SKIPPED，不影响UI/API断言结果
- **安全隔离**：数据库配置通过环境变量管理，不硬编码在脚本中

#### 4.6.5 断言报告

系统自动汇总三层断言结果，生成结构化报告：

```
断言报告
==================================================
  总计: 8  通过: 7  失败: 0  跳过: 1  错误: 0
  UI:  ✅3 ❌0 ⏭️0
  API: ✅3 ❌0 ⏭️0
  DB:  ✅1 ❌0 ⏭️1
  ✅ [UI] "提交成功"提示可见
  ✅ [API] POST /demand/create → 200
  ✅ [API] POST /demand/create → code=0
  ✅ [DB] 需求记录已写入数据库
  ⏭️ [DB] DB配置缺失，跳过DB断言
==================================================
```

## 5 运行说明

### 5.1 典型使用流程

**第一步：录制所有业务模块**

```
python cli.py record create_demand --url https://example.com/demand
python cli.py record audit_demand --url https://example.com/audit
python cli.py record confirm_demand --url https://example.com/confirm
```

**第二步：查看依赖关系**

```
python cli.py query-knowledge --graph
```

**第三步：查看编排计划**

```
python cli.py compose confirm_demand
```

**第四步：执行测试链**

```
python cli.py run confirm_demand
```

**第五步：查看测试报告**

```
python cli.py report
```

### 5.2 常见问题处理

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| 依赖图为空 | 未录制模块或AI推断未执行 | 先录制模块，推断在录制过程中自动执行 |
| 执行链不完整 | 缺少前置模块 | 补录缺失的前置模块 |
| 变量传递失败 | 模板变量名不匹配 | 检查模块定义中的变量名是否一致 |
| DB断言全部跳过 | 数据库配置缺失 | 配置MYSQL_HOST等环境变量 |
| AI推断不准确 | API数据不足或语义模糊 | 补充前端知识文档，或手动添加依赖关系 |

## 6 技术特点

1. **AI驱动的依赖推断**：通过分析API数据流自动推断模块间依赖关系，结合前端知识增强提升准确率，替代人工声明依赖
2. **拓扑排序自动编排**：将模块依赖构建为有向图，通过DFS拓扑排序自动生成执行链，支持循环依赖检测
3. **跨模块变量桥接**：通过模板变量机制实现模块间变量的自动传递，支持递归替换嵌套数据结构
4. **三层联动断言**：在单一引擎中统一调度UI/API/DB三层验证，支持变量模板跨层关联和DB层优雅降级
5. **前端知识增强**：将前端团队沉淀的接口文档注入AI上下文，显著提升依赖推断的准确率
6. **统一命令行管理**：集成录制、编排、执行、自愈、报告等全流程能力，提供一致的操作体验
